**Constraint: Quality**

* All implementations should be linted and commented. 
* If a function, class or module you are modifying is missing a docstring, add one. However, do **not** go out of your way to add docstrings everywhere they are missing.
* If a solution requires duck-typing, it is a probably a bad or hacky solution. Re-evaluate why the solution cannot leverage the strictly-typed data models and determine if duck-typing is *actually* necessary.
* Functions should fail fast and return values to halt conditional branches when possible. Overly nested logic is a code smell.
