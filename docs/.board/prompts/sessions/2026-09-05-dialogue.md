## Response to Bug B007

In my opinion, the speak node should be:

```yaml
  speak:
    - next: idle
      conditions:
        - sprite.goal
        - sprite.goal.name == constants.RequiredAssets.PLAYER.value
    - next: idle
      conditions:
        - not sprite.psyche.expression
```

e.g. update the spec to remove the `not sprite.psyche.dialogue` condition from `speak:idle`. In other words, if the player doesn't interact with the Sprite, social mechanics will eventually decrement the `ttl` until `expression` is gone. Then Sprite reenters `idle` with `dialogue` still attached, so it will naturally go back to `find:speak` in order to engage the player.

Relates to the bug about to be described, actually.

## Bug: Overview

When the Sprite gets to the remembered goal position, it enters into the `speak` intention and gets an expression appended to its frames. However, the player is not actually at that position. 

**Desired Outcome**: If the Sprite's goal is not at the location it remembers, it should enter into `wander`, then if target reenters vision, it should transition back into the Dialogue branch of `find` and back into `speak`.

**Anaylsis**: Seems like interpoints needs added to the dialogue loop from `find` to `wander` to `find` to `speak`. Anaylze the problem, determine what the Intention Loop should look like and what conditions need applied. 

**Output**: Changes to the spec, changes to the intention matrix, and tasks for removing the bug from the codebase.
