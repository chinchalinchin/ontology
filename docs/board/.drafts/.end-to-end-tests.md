#### Implement: End-to-End Integration Testing

**Overview**

Establish a deterministic, headless, tick-driven end-to-end (E2E) integration test harness in `tests/integration/` paired with a CLI record/replay workflow. The harness boots the full unmocked Engine pipeline (`Orchestrator` $\to$ `Builder` $\to$ `Loader` $\to$ `Migrator` $\to$ `Registry` $\to$ `Engine` $\to$ `Mechanics` $\to$ `Screen`) under software SDL2 (`SDL_VIDEODRIVER=dummy`, `SDL_RENDER_DRIVER=software`), feeds tick-indexed input tapes through the `Device` abstraction, executes mid-run and end-state assertions against live structured state and emitted events, and reuses `cli.utilities.dump()` and `Screen.export_render()` strictly as diagnostic artifacts on failure.

##### Specification

**1. Execution Model: Lockstep Headless Stepping**

Real-time wall-clock pacing in `Engine.start()` (`time.perf_counter()`, frame accumulators, and `time.sleep()`) introduces non-deterministic substep counts under variable CI CPU load. Integration tests execute in an unthrottled 1:1:1 lockstep cycle using fixed $\Delta t = 1.0 / \text{TARGET\_FPS}$:

$$\text{tick}(n) = \text{device.pump}() \;\to\; \text{engine.\_play}(\Delta t) \;\to\; \text{engine.\_drain}() \;\to\; \text{optional render}()$$

Rendering is skipped on non-keyframe ticks during headless runs and invoked explicitly on assertion keyframes or failure teardown to keep full multi-second scenarios in the sub-second execution range while still validating software SDL composition.

**2. Input Driver: Semantic Tape Protocol**

OS-level keystroke injection (`SDL_PushEvent`) is unreliable under `SDL_VIDEODRIVER=dummy` and does not consistently mutate the array read by `SDL_GetKeyboardState`. Because `Device` (`src/app/game/devices.py`) already isolates all hardware input, input playback sits directly beneath `Keyboard`'s edge-detection and hold-accumulation state machine via a pluggable hardware reader (`TapeDevice`).

Input sessions are authored or recorded as Pydantic-validated YAML tapes specifying:

* **Metadata**: `board`, `seed`, `screensize`, `fps`, `boot` (`direct` vs. `main_menu`).
* **Semantic Frames**: Tick-indexed directives referencing `DeviceMapping` keys (`world.goals`, `world.intentions`, `world.grips`, `world.menus`, `menu.traversal`, `menu.interactions`) rather than raw integer scancodes, resolved at load time against `configurations.mappings.keyboard` so tapes survive keybinding changes.
* **Duration & Synchronization**: Explicit `hold` tick counts (exercising bow-charge windows, sustained movement, and friction) and condition-gated `wait` barriers (e.g., wait until `board.loaded == True` or `len(board.menus) == 0`, bounded by a `max_ticks` timeout).

**3. Verification vs. Diagnostics: Why Assertions Do Not Parse Markdown Dumps**

Using `.state-dump.md.j2` as the assertion substrate introduces three structural defects:

1. **Presentation Coupling**: Template edits break assertion parsers even when engine behavior is correct.
2. **Data Loss**: `cli.utilities.filter()` and `.state-dump.md.j2` unconditionally exclude `AssetCategories.WIDGETS`, omit the active `board.menus` / `board.overlays` stack, drop sub-pixel integration remainders, and cannot observe transient mid-run states (e.g., airborne `falling` ticks or momentary `MenuEvent` / `SeasonEvent` emissions).
3. **Redundant Deserialization**: The running `Engine` already exposes strictly typed `Board`, `Asset`, `AssetState`, and `Menu` instances in memory alongside `app.models.adapters.serialize`.

Instead, verification is partitioned into four planes:

| Plane | Mechanism | Purpose |
| --- | --- | --- |
| **Domain Postconditions & Checkpoints** | Live typed queries on `Board` at named tape checkpoints and terminal tick | Primary behavioral assertions (positions, elevations, `mutators`, `meters`, `inventory`, `slots`, `switch`, `layer`, `calendar`, `plot`, `menus`). |
| **Event Bus Trace** | Passive observer wrapping `Engine._drain()` recording `(tick, Event)` | Verifies asynchronous transitions (`MenuEvent`, `StateEvent`, `TerminalEvent`, `SeasonEvent`, `UpdateEvent`) fired in exact order. |
| **Structured State Snapshots (Optional)** | Filtered `app.models.adapters.serialize(asset.state)` YAML diffs | Regression guard on canonicalized state dictionaries without Markdown parsing. |
| **Failure & Visual Artifacts** | `cli.utilities.dump()` (`.state-dump.md`, `.menus-dump.md`) + `Screen.export_render()` / `export_map()` | Human-readable debugging artifacts emitted on test failure or via CLI `replay` and uploaded by GitHub Actions. |

**4. Determinism Contract**

Identical `(board, tape, seed)` tuples must produce identical terminal states across local macOS/Linux workstations and GitHub Actions containers:

* **PRNG Seeding**: Single `seed` propagates to Python `random` (`CognitionMechanics` wander sampling) and Cython `libs.core.math.paths` (`rrt` sampling).
* **Entity Naming**: `Cradle.name()` uses a deterministic monotonic counter (`spawn-00000001`) when seeded instead of `uuid.uuid4().hex[:8]`.
* **Hydration**: `Migrator.step()` supports deterministic completion (either synchronous via `cli.utilities.hydrate()` for `boot: direct` or fixed task-count slicing instead of `time.perf_counter()` for `boot: main_menu`).

##### Architectural Analysis I

Auditing the existing codebase surfaces six concrete integration seams that must be addressed before E2E tests are reliable:

1. **Wall-Clock Coupling in `Engine.start()` (`src/app/game/engine.py`)**:
* Currently, `start()` owns the `while self.running:` loop, `device.pump()`, `_play(delta)`, `_drain()`, `_render()`, and `time.sleep()`.
* Extracting a single-step method `Engine.tick(delta: float, render: bool = True) -> bool` (returning `False` when `device.pump()` signals quit or `self.running` clears) lets `start()` remain an unchanged real-time driver while exposing lockstep stepping to both `tests/integration/` and a headless CLI `replay` subcommand.


2. **`Keyboard` Hardware Boundary (`src/app/game/devices.py`)**:
* `Keyboard` currently calls `sdl.pump()` inside `pump()` and `sdl.poll(self._scancodes)` inside `poll()`, while encapsulating all context-switching (`DeviceContexts.WORLD` $\leftrightarrow$ `DeviceContexts.MENU`), `_is_rising_edge()`, `_latched`, and hold-tick accumulation (`holds`).
* Refactoring those two raw hardware reads into overridable hooks (`_pump_raw()` and `_poll_raw(scancodes)`) allows:
* `TapeDevice(Keyboard)` to inject scheduled scancodes while exercising 100% of `Keyboard`'s rising-edge, hold-duration, and context-isolation logic.
* `RecorderDevice(Keyboard)` to wrap live `sdl.pump()` / `sdl.poll()` calls and emit compressed semantic tape frames during normal `src/main.py start --record` play sessions.




3. **Non-Determinism Sources (`migrator.py`, `cradle.py`, `paths.pyx`, `cognition`)**:
* `Migrator.step(budget_ms=16)` checks `(time.perf_counter() - start) * 1000 > budget_ms`. Under CI load, `LoadController` will take a variable number of frames to emit `TerminalEvent`. Adding an optional `max_tasks: Optional[int] = None` parameter to `Migrator.step()` (with `budget_ms=None` disabling the wall clock) guarantees exact tick counts during `MainMenu` $\to$ `LoadMenu` $\to$ `Board` E2E runs.
* `Cradle.name()` calls `uuid.uuid4().hex[:8]`, causing spawned projectiles, collectables, passive splashes, compositions, and shorelines to receive non-deterministic names. Adding an optional sequential counter mode on `Cradle` (reset per seeded test run) makes spawned asset names reproducible.
* `libs.core.math.paths.rrt` and `CognitionMechanics` (`wander`) sample random numbers; exposing a `seed(value: int)` hook in `paths.pyx` and seeding Python's `random` state before hydration eliminates trajectory drift.


4. **Observability Without Mocking (`engine.py` & `cli/utilities.py`)**:
* `Engine._drain()` discards events after dispatching to `self.handlers`. Adding an optional `on_event: Optional[Callable[[Any], None]]` hook or ring-buffer `trace` list captures every drained event with its tick index without mutating `EventHandler` contracts.
* `cli.utilities.dump()` hardcodes `settings.DUMP_DIR` as the destination and derives filenames from `datetime.datetime.now()`. Adding an optional `out_path: Optional[Path]` parameter lets pytest failure hooks write deterministic `<test_name>.state-dump.md` and `<test_name>.menus-dump.md` files into a dedicated CI artifact directory.


5. **SDL2 & Cython Teardown Discipline Across Multi-Test Processes (`src/main.py`, `tests/integration/`)**:
* `src/main.py` explicitly notes: *"Strictly ordered teardown to prevent post-SDL_Quit use-after-free"* (`engine.stop(); del engine; gc.collect(); quit_sdl()`).
* Unlike `tests/unit/fixtures/components.py` (which monkeypatches `libs.graphics.render` via `mock_render`), integration tests allocate real software `SDL_Texture*` and `TTF_Font*` wrappers inside `Registry` and `Screen`. Every integration test fixture must enforce `engine.stop()` $\to$ `del engine` $\to$ `gc.collect()` $\to$ `quit_sdl()` in a `try/finally` block (or isolate each test's `Engine` lifecycle cleanly) to prevent double-free segfaults under `pytest-xdist`.


6. **CI Pipeline Alignment (`.github/workflows/tests.yml`)**:
* The existing `chinchalinchin/ontology-builder:latest` container already ships with `libsdl2-dev`, `libsdl2-image-dev`, `libsdl2-ttf-dev`, `libsdl2-mixer-dev`, Python 3.14, and Cython caching, and runs with `SDL_VIDEODRIVER=dummy` and `SDL_AUDIODRIVER=dummy`.
* Integration tests can run in a parallel or follow-up job inside `.github/workflows/tests.yml` (reusing the same `cache-cython` key) with `SDL_RENDER_DRIVER=software`, uploading `tests/integration/artifacts/` via `actions/upload-artifact@v4` with `if: failure()`.



##### Goals

###### Goal: Lockstep Engine Stepping & Event Tracing

Decouple single-tick simulation from wall-clock pacing in `Engine` and add non-invasive event tracing so headless tests can step deterministically and inspect every asynchronous transition.

```python
# src/app/game/engine.py
class Engine:
    def tick(self, delta: float = 1.0 / settings.TARGET_FPS, render: bool = True) -> bool:
        """Executes a single deterministic simulation tick. Returns False on quit."""
        if self.board.device is not None and self.board.device.pump():
            self.running = False
            return False

        self._play(delta)
        self._drain()

        if render:
            self._render()

        return self.running

```

* `Engine.start()` delegates its fixed-timestep substep to `_play(delta)` + `_drain()` as before, while headless runners drive `engine.tick(delta, render=is_keyframe)`.
* `Engine._drain()` optionally appends `(tick_index, event)` to an attached `EventTrace` observer before handler execution.

###### Goal: Semantic Input Tape Schema, Replay Driver & Live Recorder

Introduce a Pydantic-validated YAML tape format (`app.models.config.tapes` or `app.models.testing`) and two `Keyboard` subclasses sharing `Keyboard`'s exact context and edge-detection state machine.

```yaml
# tests/integration/tapes/chest-and-bridge.yaml
board: world-testbed
seed: 1337
boot: direct          # 'direct' (synchronous hydrate) | 'main_menu'
screensize:
  w: 480
  l: 480
fps: 60
frames:
  - tick: 0
    hold: 45
    world:
      goals: [down]
  - tick: 45
    hold: 30
    world:
      goals: [right]
  - tick: 75
    checkpoint: crossed-bridge
  - tick: 80
    world:
      intentions: interact
  - tick: 82
    checkpoint: chest-menu-open
    menu:
      interactions: cancel
  - tick: 90
    quit: true

```

```python
# src/app/game/devices.py
class Keyboard(Device):
    def _pump_raw(self) -> tuple[bool, list[int]]:
        return sdl.pump()

    def _poll_raw(self, scancodes: tuple[int, ...]) -> tuple[int, ...]:
        return sdl.poll(scancodes)

class TapeDevice(Keyboard):
    """Feeds scheduled semantic frames into Keyboard's rising-edge and hold logic."""
    ...

class RecorderDevice(Keyboard):
    """Pass-through Keyboard wrapper that records active semantic deltas per tick."""
    ...

```

* Resolving semantic keys through `DeviceMapping` ensures `TapeDevice` exercises the same `WORLD`/`MENU` context transitions, `_latched` rising edges, and `holds` counters as real hardware play.
* `src/main.py start [board] --record <tape.yaml>` lets you play a scenario once interactively, save the tape, trim/annotate checkpoints, and commit it to `tests/integration/tapes/`.

###### Goal: Deterministic Simulation Boundary

Eliminate all sources of cross-run variance across hydration, spawning, and stochastic mechanics when running under a configured seed.

* `Migrator.step(budget_ms=16, max_tasks=None)`: when `max_tasks` is set, yield strictly by task count rather than `time.perf_counter()`.
* `Cradle`: support an optional deterministic sequence generator (`counter: Optional[itertools.count]`) so `Cradle.name()` emits `spawn-00000001`, `spawn-00000002`, etc.
* `libs.core.math.paths`: expose `seed(int)` to seed Cython's PRNG alongside Python's `random.seed(int)` prior to hydration.

###### Goal: Multi-Plane Integration Harness & Failure Diagnostics

Build a fixture-driven pytest harness in `tests/integration/` that runs unmocked scenarios, supports mid-run checkpoint callbacks, and automatically exports human-readable diagnostics on failure.

```python
# Conceptual scenario in tests/integration/scenarios/test_hydrodynamics_and_interaction.py
@pytest.mark.integration
@pytest.mark.workflow_fluids
def test_bridge_crossing_and_chest_interaction(e2e_runner):
    run = e2e_runner.load("tapes/chest-and-bridge.yaml")

    # Mid-run checkpoint assertion
    run.until("crossed-bridge")
    player = run.board.player()
    assert player.state.mutators.triggers.submerged is False
    assert player.state.position.y > 290

    # Menu transition & EventTrace assertion
    run.until("chest-menu-open")
    assert run.board.paused is True
    assert len(run.board.menus) == 1
    assert run.events.has(MenuEvent, id="inventory")

    # Complete tape & verify final domain state
    run.finish()
    assert run.board.paused is False
    assert len(run.board.menus) == 0

```

* On any assertion failure, the pytest hook (`pytest_runtest_makereport`) automatically invokes:
1. `cli.utilities.dump(..., Dumps.STATE, out_path=...)` (producing the `.state-dump.md` report).
2. `cli.utilities.dump(..., Dumps.MENUS, out_path=...)` (producing the `.menus-dump.md` report).
3. `screen.export_render(...)` and `screen.export_map(...)` (producing PNG snapshots of the exact failure tick).
4. Event trace dump (`<test>.events.yaml`) showing every event drained up to failure.



###### Goal: CLI Replay Subcommand & CI Pipeline Integration

Expose headless tape execution directly through `src/main.py` and integrate the E2E suite into GitHub Actions.

* **CLI**: `python src/main.py replay <tape.yaml> [--out <artifact-dir>] [--dump-state] [--dump-menus] [--render-final]` runs a tape headlessly using the same runner as pytest, enabling fast local iteration and visual debugging.
* **CI**: Add an `integration` job to `.github/workflows/tests.yml` running `uv run pytest tests/integration/` with `SDL_VIDEODRIVER=dummy`, `SDL_AUDIODRIVER=dummy`, `SDL_RENDER_DRIVER=software`, uploading failure artifacts (state dumps, menu dumps, event traces, PNG renders) on failure.
