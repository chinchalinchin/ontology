#### Refactor: Phase 07.01: Elevation Sorting

**Overview**

This phase deprecates the legacy `height` coordinate hack, renames the categorical `depth` attribute to `elevation` across all data models and configuration schemas, and establishes a discrete multi-tier 2.5D spatial architecture. The rendering engine is updated to enforce strict lexicographical sorting: primary sorting evaluates discrete integer $Z$-plane elevation tiers ($\text{elevation} \in \mathbb{Z}$), and secondary sorting evaluates continuous in-tier geometric ground perspective ($y + l$). In addition, `stairs` is promoted to a dedicated `Crafts` asset instance, complete with interaction-driven elevation transitions and elevation-filtered physical boundary collision checks.

##### Specification

1. **State & Property Nomenclature**:
    
* Deprecate `height` on `AssetState` and all derived models.
* Rename `depth` to `elevation` across all state models, schemas, Cython primitives, and YAML configs (defaulting to `elevation: 0`).
* Add optional `elevation_span: Optional[Tuple[int, int]]` (defaulting to `(elevation, elevation)`) to physical `Hitbox` representations to support vertical structures that obstruct multiple tiers (e.g., cliff facades spanning elevation $0 \to 1$).

2. **Rendering Pipeline Invariant**:

* The Painter's Algorithm in `Screen._sort()` evaluates:

$$\text{sort\_key}(A) = \Big(A.\text{state.elevation},\; \text{int}(A.\text{state.position.y} + A.\text{dimensions.l})\Big)$$

* Rendering iterates monotonically from lowest elevation to highest elevation, sorting dynamic perspective strictly within each discrete tier.


3. **Taxonomy & Crafts Expansion (`crafts.stairs`)**:

* Register `stairs` as a first-class instance under `AssetCategories.CRAFTS.value`.
* Provide `StairProperties` ($w, l, \text{mass} = -1, \text{hitboxes}, \text{cost}$) and `StairState` ($\text{orientation}, \text{elevation}, \text{delta} = 1$).
* Register flyweight recipe components: `OrientedFrame`, `NoAnimation`, and `DynamicHitbox`.

4. **Elevation Transition Mechanics (`InteractionMechanics`)**:

* Stairs act as spatial sensors ($m = -1$) that bridge tier $E$ and tier $E + 1$.
* Directional threshold detection: Entering along the ascent vector increments character elevation ($E_{\text{sprite}} \leftarrow E_{\text{stairs}} + 1$); exiting along the descent vector decrements character elevation ($E_{\text{sprite}} \leftarrow E_{\text{stairs}}$).

5. **Collision & Constraint Filtering (`CollisionMechanics`)**:

* Broad-phase and narrow-phase collision resolution is partitioned by elevation tier:

$$\text{CanCollide}(A, B) \iff \big[\min(E_A), \max(E_A)\big] \cap \big[\min(E_B), \max(E_B)\big] \neq \emptyset$$

* Environmental perimeters generated by `Perimeter` partition per layer and elevation tier (`board.perimeters[layer][elevation]`).

##### Architectural Analysis I

The prior reliance on `height` was a compensatory mechanism for a flat 2D coordinate system attempting to fake 3D occlusions. Binding `height: bind(root.height)` or forcing `height: -100` flattened multi-planar geometry into a single dimension, resulting in Z-fighting, jittering along seams, and failure on inclined planes (stairs).

Promoting `elevation` to an integer spatial coordinate ($Z$) eliminates sorting ambiguity:

* **Substrate Floors**: `elevation: -1` or `elevation: 0` with $y+l=0$.
* **Ground Facades & Entities**: `elevation: 0`, sorting dynamically via $y + l$.
* **Terraces & Balconies**: `elevation: 1`, sorting dynamically via $y + l$.
* **Canopies & Overhangs**: `elevation: 2`, guaranteed to paint over all characters at elevation $0$ and $1$.

Regarding physical collisions: If collision resolution only evaluates entities where $E_A == E_B$, an entity on elevation $0$ can never hit a platform deck on elevation $1$. However, the front-facing vertical wall of the platform must still block entities walking on elevation $0$. Decoupling the platform asset into a vertical facade wall at elevation $0$ ($m = 0$) and a floor deck at elevation $1$ ($m = -1$, walkable substrate) solves this natively without complex 3D swept-volume math.

###### Goal: Elevation-Aware Spatial Mechanics & Collision Filtering

Filter broad-phase candidate pairs in `CollisionMechanics` by matching elevation tiers before narrow-phase AABB calculations.

```python
# app/game/logic/mechanics/spatial/collision.py
def update(self, board: Board, delta: float, bus: collections.deque, payload: DevicePayload) -> None:
    for layer in board.layers():
        weights = board.weights(layer)
        weights_by_elevation = collections.defaultdict(list)
        for w in weights:
            weights_by_elevation[w.state.elevation].append(w)

        for elevation, tier_weights in weights_by_elevation.items():
            perimeters = board.perimeters.get(layer, {}).get(elevation, [])
            if perimeters:
                dynamics = [w for w in tier_weights if getattr(w.properties, 'mass', 0) > 0 or w.taxonomy.instance == AssetInstances.PLAYERS.value]
                for asset, boundary in self.constrain(dynamics, perimeters):
                    self._boundary(asset, boundary)

            for a, b in self.collisions(tier_weights):
                self._resolve(a, b)

```

###### Goal: Dynamic Elevation Transitioning on Inclines

Implement threshold tracking in `InteractionMechanics` to shift a sprite's elevation tier upon traversing stairs.

```python
# app/game/logic/mechanics/world/interaction.py
def _traverse_stairs(self, sprite: Asset, stairs: Asset) -> None:
    # Check vertical progression across tread bounds
    tread_progress = (sprite.state.position.y + sprite.dimensions.l - stairs.state.position.y) / stairs.dimensions.l
    if tread_progress <= 0.2:  # Reached top landing
        sprite.state.elevation = stairs.state.elevation + 1
    elif tread_progress >= 0.8:  # Reached bottom landing
        sprite.state.elevation = stairs.state.elevation

```

##### Debugging

Original sessions omitted for brevity. Below is the comprehensive audit of architectural and implementation changes introduced during this session.

###### Session I

**1. The Substrate Hierarchy Registry & Dynamic Elevation Fallback**

* **Original Spec**: `elevation` was conceived as a static integer field (`elevation: int = 0`) on `AssetState` replacing `depth` and `height`. All substrates and ground entities defaulted to `0`.

* **Added / Changed**:
  * Created `settings.SUBSTRATES` as a canonical instance-keyed mapping assigning negative integer tiers to terrain substrates (`back: -4`, `fluids: -3`, `shorelines: -2`, `bridges: -1`).
  * Updated `AssetState.elevation` to `Optional[int] = None`.
  * Added dynamic `@property` and `@elevation.setter` on `Asset` to lazily resolve substrate defaults when unset, while preserving explicit state overrides for upper-tier bridges or custom elevations.

**2. Three-Key Lexicographical Painter's Algorithm (`elevation`, `ground_y`, `priority`)**

* **Original Spec**: `Screen._sort` evaluated a 2-tuple:

$$
\text{sort\_key}(A) = (A.\text{state.elevation},\; \text{int}(A.\text{state.position.y} + A.\text{dimensions.l}))
$$


* **Added / Changed**:
  * Proved that a 2-tuple cannot distinguish inset wall fixtures from objects standing behind buildings.
  * Added `priority: int = 0` to `AssetProperties` as an archetype-level surface tie-breaker.
  * Added `anchor: int = 0` to `AssetState` to allow wall fixtures to align with their host facade's ground contact line.
  * Expanded `Screen._sort` to evaluate `(asset.elevation, ground_y, asset.properties.priority)` with $\text{ground\_y} = \text{int}(\text{pos.y} + l + \text{anchor})$.

**3. Sanitation of `Perimeter` Boundary Extraction & Dynamic Body Exclusion**

* **Original Spec**: `Perimeter.extract()` partitioned hulls by `(layer, elevation)` matching static architecture to `elevation`.

* **Added / Changed**:
  * Identified that `Perimeter.extract()` was naively pulling dynamic bodies (`mass > 0`, `crates`, `chests`) into the mathematical obstacle hull, baking initial coordinates of movable furniture (like `wood-bookshelf`) into boundary perimeters and triggering recursive collision jitter loops in `physics.constrain`.
  * Added an explicit static filter in `Perimeter.extract()` excluding all movable bodies and dynamic containers.
  * Added substrate floor inclusion for Tier 0: ensured room floorboards (`elevation <= 0` with $m = -1$) are included in boundary synthesis so interior spaces do not generate inverted perimeter edges around furniture footprints.

**4. Non-Positive Elevation Clamping for Physics & Hydrology**

* **Original Spec**: Broad-phase and narrow-phase collision mechanics partitioned purely by matching discrete elevation integers ($E_A == E_B$).

* **Added / Changed**:
  * With substrates assigned negative elevations (`-4` to `-1`), physical partitioning risked fragmenting ground-level interactions.
  * Updated `CollisionMechanics.update()` to map non-positive elevations to Tier 0 (`max(0, w.elevation)`), unifying ground entities while preserving isolation for upper tiers ($E \ge 1$).
  * Updated `Actuator._collect_obstacles()` to clamp non-positive fluid elevations to 0 (`fluid.elevation if fluid.elevation > 0 else 0`), ensuring fluid stream raycasts interact with ground-level obstacle hulls correctly.
  * Updated `Board.weights()` and `Board.obstacles()` queries to treat `elevation == 0` as matching all entities where `elevation <= 0`.

**5. Decomposer Unique Nomenclature Generation (Preexisting Defect Resolution)**

* **Original Spec**: Only called for removing `node_height` tracking and `bind(root.height)` parsing from `Decomposer`.

* **Added / Changed**:
  * Discovered that `Decomposer._hydrate_state()` discarded `kwargs.get('name')` for non-strut child components, assigning identical generated names to sibling entities under the same parent strut (e.g., 3 doors named `door-strut-castle-dawn-exterior-3-3`, 4 interior doors named `door-strut-castle-atrium-floor-3-3`).
  * Fixed nomenclature generation to preserve the component's unique configuration name: `<instance>-<parent_name>-<comp_name>-<increment>`.

###### Session II

**1. Entity Physics & Mass Normalization**

* **Model Default Update (`app.models.properties.SheetProperties`)**:
  * Set `mass: int = 1` by default (previously `0`) across all sheet entities.
* **ECS Decoupling**:
  * Eliminated categorical taxonomy checks (`taxonomy.instance == AssetInstances.PLAYERS.value`) in favor of physics-driven predicates (`getattr(properties, 'mass', 0) > 0`).
  * NPC `sprites` are now dynamically recognized as movable bodies, enabling them to naturally collide, be pushed by kinematic players, obey perimeter boundaries, and traverse stairs without taxonomy branch exceptions.

**2. Incline Traversal & Kinematic Foot-Anchor Gating**

* **Sensory Foot-Anchor Projection (`CollisionMechanics._traverse_stairs`)**:

* Replaced bounding box leading edge evaluations (`pos.x + w`, `pos.y + l`) with centered ground contact coordinates:

$$
f_x = \text{pos.x} + \left\lfloor\frac{w}{2}\right\rfloor, \quad f_y = \text{pos.y} + l
$$

* Normalized spatial progress across stair dimensions:

$$
\text{tread\_progress}_y = \frac{f_y - \text{stair.y}}{\text{stair.l}}, \quad \text{tread\_progress}_x = \frac{f_x - \text{stair.x}}{\text{stair.w}}
$$

* Resolved bounding-box saturation where sprites with $w \ge 0.2 \cdot \text{stair.w}$ prematurely clamped to $1.0$ upon first contact.

* **Velocity Hysteresis & Inversion Fixes**:

* Tied tier switching to directional velocity gating ($v_y < 0$ / $v_y > 0$, $v_x < 0$ / $v_x > 0$), preventing premature snapping when grazing stair edges.
* Corrected threshold target inversion on south-facing stairs (`Directions.DOWN.value`), mapping summit landings ($u \le 0.2, v_y < 0$) to $E_{\text{base}}$ and base landings ($u \ge 0.8, v_y > 0$) to $E_{\text{top}}$.

**3. Stair Sensor Classification**

* **Asset Configuration (`src/assets/crafts/struts/stairs.yaml`)**:
  * Reclassified `stairs-stone` mass to `mass: -1` (sensor body).
* **Physics Collision Bypass**:
  * Excluded stair entities from `Board.weights()` and `Board.obstacles()`, eliminating infinite-mass static body collision blocks and physics jitter during incline climbs while preserving spatial trigger detection.

**4. Declarative Anchor Macro Compilation (`anchor(target)`)**

* **State Model Schema Typing (`app.models.state.core.AssetState`)**:

* Updated attribute typing to `anchor: Union[int, str] = 0`.
* Allows Pydantic's `TypeAdapter(ConfigurationSchema).validate_python()` to parse declarative macro strings in YAML without `int_parsing` validation errors.

* **Two-Pass Macro Resolution Compiler (`app.services.generators.game.decomposer.Decomposer`)**:

* **Pass 1 (Scope Indexing)**: Scans node/branch components into `scope_lookup: Dict[str, Tuple[AssetState, str, str]]`, recording local sibling names alongside their Category, Instance, and Asset ID.

* **Pass 2 (Evaluation & Downcasting)**: Compiles `anchor(...)` directives into concrete ground-alignment offsets before ECS asset instantiation:

$$
\text{anchor} = (y_{\text{target}} + l_{\text{target}}) - (y_{\text{self}} + l_{\text{self}})
$$

* Supported targets:
  * `anchor(parent)`: Anchors to the immediate parent strut's baseline.
  * `anchor(root)`: Anchors to the root strut's baseline.
  * `anchor(<sibling_name>)`: Anchors to a named sibling defined within the same branch.

* **Runtime Invariant**: Enforces `kwargs['anchor'] = int(...)`, ensuring `Screen._sort` receives a strictly typed `int` for Painter's Algorithm ground-depth calculations (`ground_y = int(pos.y + dim_l + anchor)`).
