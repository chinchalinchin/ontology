##### Overview

A critical rendering pipeline failure was observed during live execution (`start` CLI). The application window initialized correctly but remained completely black. Asset state migration, user input polling, and logic calculations were actively functioning in the background, but the rendering instructions failed to present any visual output to the screen.

###### Root Cause Analysis

The failure resulted from two independent architectural defects that compounded: an X11 window context suspension and an infinite time-trap in the Python game loop.

**1. X11 Context Suspension (Cython VRAM Allocation Failure)**

The application is designed to hide the SDL window (`SDL_WINDOW_HIDDEN`) during launch to prevent exposing a blank screen while the `Registry` parses asset files into GPU memory. 

On Linux environments utilizing X11/OpenGL, hardware-accelerated drivers aggressively optimize resource allocation. When `Registry` and `Screen` requested VRAM targets (`SDL_TEXTUREACCESS_TARGET`) against an unmapped, hidden window, the GPU silently discarded the `SDL_SetRenderTarget` commands. Because Cython executed these commands as raw C-pointers without intercepting the `-1` error returns, the `bg_canvas` and all dynamic `Persona` textures were rendered into VRAM as perfectly transparent $0 \times 0$ voids.

Headless CLI commands (`prerender`/`render`) bypassed this defect entirely because they trigger `SDL_RENDERER_SOFTWARE`, which operates on system memory and ignores window visibility state.

**2. Engine Clock Time-Trap (Infinite Spin)**

Simultaneously, the main execution sequence in `src/app/game/engine.py` suffered from a logical trap. The `current_time` variable was evaluated outside the active `while not self.board.paused:` loop. 

Consequently, time halted the moment the inner loop was entered. The `accumulator` failed to accrue physical delta, bypassing all `Mechanic.update()` physics and state mutations. The engine entered an unthrottled infinite loop, passing the exact same frozen $t=0$ coordinates to the Cython bridge thousands of times a second.

**Remediation**

1. **Clock Refactor:** The inner `while` loop within the `Engine` was converted to an `if` block, ensuring `current_time` evaluation occurs sequentially with every tick, restoring 60Hz physics processing.
2. **Context Validation (OS Mapping):** The `render.show()` invocation was relocated within `Orchestrator.init()` to execute *before* `Registry` and `Screen` allocate any VRAM targets[cite: 1]. By mapping the window to the OS compositor early, the OpenGL context fully validates, preventing the silent drop of `SDL_SetRenderTarget` calls.
3. **Cinematic Loading Screen:** To preserve the UX goal of hiding the load sequence, `libs/graphics/render.pyx` was updated to explicitly paint the uninitialized window buffer with solid black and call `SDL_RenderPresent()` during the `show()` execution. 

**Lessons Learned**

* **Trust but Verify C-Returns:** Never assume a low-level C-call succeeds just because it compiles. Hardware-accelerated pipelines fail silently. Critical bindings must check the integer return codes of functions like `SDL_RenderCopy` and `SDL_SetRenderTarget`.
* **OS Compositor Dependencies:** GPU resource allocation is tightly coupled to OS window managers. Never allocate dynamic textures or composite framebuffers against an unmapped or hidden window unless strictly using system-memory software rasterizers.
* **Clock Isolation:** Game engine clock calculations must govern the absolute outer boundary of the execution loop to prevent state-suspension traps.
