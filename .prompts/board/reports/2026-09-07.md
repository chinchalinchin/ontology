##### Root Cause Analysis

**Issue Description:**

Text in the Dialogue menu was failing to render visibly on the screen. Once corrected, attempts to modify the text's size were ignored by the engine.

**Root Causes:**

* **Alpha Channel Truncation:** The `RGBA` dataclass defined the alpha channel (`a`) as a `float`. The YAML configuration provided `1.0`. However, the underlying SDL Cython bindings expect an 8-bit integer (0-255) for color channels. When passed to the C-level struct, `1.0` was truncated to `1`, resulting in a near-invisible opacity of 0.4%.
* **Margin Overflow:** The `FontProperties` dataclass incorrectly typed `margins` as an `int`. The YAML configuration provided `5`, which Pydantic parsed as an integer. The Cython rendering loop expects this value to be a floating-point percentage, calculating the Y-offset by multiplying the asset's length by the margin. Multiplying the 64-pixel canvas length by 5 pushed the text coordinates completely outside the rendering bounds.
* **Silently Dropped Configuration:** Pydantic V2 is strictly schema-driven and silently drops unmapped keys during validation. Because the `size` attribute was omitted from the `FontProperties` dataclass definition, Pydantic discarded the user's `size` configuration before it ever reached the Registry.


**How Font Properties Work**

Fonts in Ontology do not function like standard physical game entities.

* **Stateless and Runtime-Initialized:** Fonts are stateless assets that are initialized at runtime rather than being deployed onto the physical Game Board.
* **Encapsulation:** A Font asset serves as a wrapper that encapsulates both the physical `.ttf` file (the script) and the specific styling applied to it.
* **Storage and Retrieval:** Each styled Font is stored in the game's Registry, keyed by its file name.
* **Screen Utilization:** Whenever the game loop requires text to be displayed, the Screen component retrieves the styled Font directly from the Registry and passes it to the rendering engine.

##### Remediation

1. **Update the RGBA Schema:** Modify the `RGBA` dataclass in `app/models/properties.py` to strongly type the `a` (alpha) attribute as an `int` instead of a `float`.
2. **Update the FontProperties Schema:** Modify the `FontProperties` dataclass to explicitly define `size: int = 24` to prevent Pydantic from silently dropping the key. Change the `margins` attribute from an `int` to a `float`.
3. **Correct the YAML Configuration:** Adjust the `src/assets/fonts/main.yaml` file to use an integer for the alpha channel (`a: 255`) and a floating-point percentage for the margins (`margins: 0.05`).


##### Lessons Learned

* **Pydantic Schema Strictness:** Pydantic validation acts as a strict filter; if a configuration key is not explicitly defined in the corresponding dataclass, it will not survive the hydration process.
* **Python-to-C Type Boundary:** Data types must be rigorously aligned between Python validation schemas and Cython C-structs. Relying on implicit casting (like Python floats to C integers) leads to silent geometric and visual bugs that are difficult to trace.
* **Holistic Validation:** When adding new capabilities to an engine (like dynamic font sizing), the property must be added to the YAML, the validation schema, and the downstream rendering consumption logic simultaneously.
